# 从软件工程角度理解 FedSTHG

## 先理解三个不同的“节点”

1. 空间图节点是一个脑区。它的输入特征不是一个标量，而是该脑区与全部116个脑区的带符号连接行向量。
2. 时间图节点是一个动态窗口。其特征是这个窗口整张116×116连接矩阵的6670个上三角数，经投影后得到64维向量。
3. 受试者图节点是当前客户端当前批次的一名受试者。它连接的是人的128维融合表征，不是ROI，也不是跨医院的人。

这三个域不能混用。`graphs.py`负责结构，`model.py`负责如何从特征生成这些域的表征。

## 为什么同时保留 GIN 和 HGIN

假设节点特征为 a=1、b=3、c=5，有超边{a,b}和{b,c}。HGIN先产生超边均值2和4，随后a收到2、b收到6、c收到4。注意b收到的是两个超边消息的**和**，不是平均。这正是`H @ ((H.T @ X)/edge_size)`。之后再加自己的`(1+epsilon)*X`，经过MLP与LayerNorm。

GIN则直接把邻居特征求和。两者不是先后处理：各自从同一个投影后的X开始，独立传播两层后拼接。`ParallelPaths.forward`里两次`x=x0`就是这一契约。`test_layers.py`通过钩子检查两条路径确实从同一输入出发。

## 可学习构图为什么没有对邻居索引求导

时间投影和位置嵌入是可学习的，每次前向都会用新特征重新计算余弦相似度。kNN选中的离散成员没有连续梯度；梯度仍通过被传播的节点特征回到投影和位置参数。这里没有引入论文未规定的软图/注意力边权来“解决”离散构图问题。

## 从节点到分类

空间116个节点取平均；时间W个窗口按可学习query产生权重并加权求和。两个128维向量送入一个输出2个数的softmax门，得到空间和时间的比例。按比例相加后仍是128维，然后线性投影、ReLU、LayerNorm、dropout。

一致性损失只要求两个池化向量方向接近，强度由lambda控制。它不要求116个ROI与W个窗口一一对齐，也不要求两条分支逐元素完全相同。

本地受试者图只用当前批次特征构图，不读取标签。只来一名受试者时必须整个绕过细化层，包括归一化；`SubjectRefinement.forward`直接返回输入对象。否则单人模型会与论文描述不一致。

## 联邦训练中的三个对象

把全局编码器理解为服务器保存的共享版本，把个性化编码器理解为每个医院长久保留的分支，把本地模块理解为医院自己的适配/分类器。

每轮先复制全局版本，和本地模块一起学一轮；上传这份临时编码器给服务器。服务器按训练人数平均得到新全局版本。然后恢复该医院原有的个性化编码器，用新全局版本做固定参照再学一轮。本地模块接着阶段I的状态继续更新。

最容易犯的错误是用新全局参数覆盖个性化编码器。这样虽然程序也能训练，却不再是论文的持久个性化流程。`test_phase_paths_and_frozen_reference`专门保护这件事。最终推理使用`personal[site] + local[site]`，不使用服务器模型。

## 如何判断复现成功

测试通过只能证明一组数学和工程契约成立。真实数据训练能证明流程可运行；达到论文数字还需要相同队列、预处理、配置和评价方法。本项目把这三层证据分开保存。参数量不符或成绩较低时，先核对缺失条件，不通过改算法或用测试集挑配置掩盖差异。

建议阅读顺序：`docs/research.md` → `preprocessing.py` → `graphs.py` → `layers.py` → `model.py` → `federated.py` → `experiment.py`，每读完一层运行对应测试。
